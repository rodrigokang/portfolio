Data Extraction¶

The transaction history is extracted at the order level. Keeping the data at this level preserves the temporal structure needed to define calibration and validation windows, build customer-level features, and construct the churn target without using future information.

In [5]:
query = """
SELECT
    c.customerid,
    CASE
        WHEN c.personid IS NOT NULL THEN 'Individual'
        WHEN c.storeid IS NOT NULL THEN 'Store'
        ELSE 'Unknown'
    END AS customer_type,
    soh.salesorderid,
    soh.orderdate,
    soh.totaldue,
    st.name AS territory
FROM sales.customer AS c
JOIN sales.salesorderheader AS soh
    ON c.customerid = soh.customerid
LEFT JOIN sales.salesterritory AS st
    ON soh.territoryid = st.territoryid
WHERE soh.status = 5
ORDER BY
    c.customerid,
    soh.orderdate,
    soh.salesorderid
"""

transactions = pd.read_sql(query, engine)

Calibration and Validation Periods¶

Customer features are constructed using a calibration period ending on June 30, 2024. Customer activity during the subsequent twelve-month validation period is used to determine whether each customer remained active or became inactive.

This temporal split ensures that all predictive variables are calculated using information available at the time the prediction would have been made.

RFM Feature Construction¶

Customer-level RFM features are computed using transactions observed during the calibration period only.

Recency is defined as the number of days since the customer's most recent purchase before the calibration cutoff date. Frequency corresponds to the number of orders placed during the calibration period, while Monetary represents the cumulative revenue generated by the customer over the same period.

Churn Target Construction¶

In a non-contractual retail setting, customer churn is not directly observable because customers are free to purchase at any time without formally terminating their relationship with the company.

For this analysis, a customer is considered inactive if the time elapsed since their most recent observed purchase exceeds 365 days at the end of the validation period. This operational definition provides a practical benchmark for supervised churn modeling while remaining consistent with the notion of customer inactivity used in the customer-base analysis literature.

Modeling Strategy¶

The objective is to evaluate both classification algorithms and class-balancing strategies for customer churn prediction.

Because inactive customers represent a minority of the customer base, several resampling techniques are considered. Each resampling strategy is combined with multiple classification algorithms and evaluated using a common set of performance metrics.

The best-performing model is selected for detailed diagnostic analysis and subsequently compared with a probabilistic customer-base model based on the BG/NBD framework.

def evaluate_classifier(
    model_name,
    resampling_name,
    pipeline,
    X_train,
    y_train,
    X_test,
    y_test
):
    """
    Evaluate a classification model using a fixed
    training and testing partition.

    Input
    -----
    model_name : str
        Name of the classification algorithm.

    resampling_name : str
        Name of the resampling strategy.

    pipeline : imblearn.pipeline.Pipeline
        Modeling pipeline including preprocessing,
        optional resampling, and classifier.

    X_train : pandas.DataFrame
        Training predictors.

    y_train : pandas.Series
        Training target variable.

    X_test : pandas.DataFrame
        Testing predictors.

    y_test : pandas.Series
        Testing target variable.

    Output
    ------
    dict
        Dictionary containing performance metrics
        and the fitted pipeline.

    Author
    ------
    Rodrigo Kang
    """

    pipeline.fit(
        X_train,
        y_train
    )

    y_pred = pipeline.predict(
        X_test
    )

    y_prob = pipeline.predict_proba(
        X_test
    )[:, 1]

    return {
        "model": model_name,
        "resampling": resampling_name,
        "accuracy": accuracy_score(
            y_test,
            y_pred
        ),
        "precision": precision_score(
            y_test,
            y_pred
        ),
        "recall": recall_score(
            y_test,
            y_pred
        ),
        "f1_score": f1_score(
            y_test,
            y_pred
        ),
        "roc_auc": roc_auc_score(
            y_test,
            y_prob
        ),
        "pr_auc": average_precision_score(
            y_test,
            y_prob
        ),
        "pipeline": pipeline
    }

Benchmark Execution¶

Each classifier is combined with each resampling strategy and evaluated on the same holdout dataset.

Resampling is applied exclusively to the training data through the modeling pipeline, preventing information leakage from the test set.

In [35]:
benchmark_results = []

for resampling_name, sampler in (
    resampling_strategies.items()
):

    for model_name, model in (
        models.items()
    ):

        steps = [
            (
                "scaler",
                StandardScaler()
            )
        ]

        if sampler is not None:

            steps.append(
                (
                    "sampler",
                    sampler
                )
            )

        steps.append(
            (
                "model",
                model
            )
        )

        pipeline = ImbPipeline(
            steps=steps
        )

        result = evaluate_classifier(
            model_name=model_name,
            resampling_name=resampling_name,
            pipeline=pipeline,
            X_train=X_train,
            y_train=y_train,
            X_test=X_test,
            y_test=y_test
        )

        benchmark_results.append(
            result
        )

Kolmogorov-Smirnov Statistic¶

The Kolmogorov-Smirnov (KS) statistic measures the maximum separation between the cumulative distributions of churners and non-churners.

In customer analytics and credit risk applications, the KS statistic is commonly used to evaluate the discriminatory power of predictive models.

In [42]:
ks_data = pd.DataFrame({
    "actual": y_test,
    "score": y_prob_best
})

ks_data["non_churn"] = (
    ks_data["actual"] == 0
).astype(int)

ks_data["churn"] = (
    ks_data["actual"] == 1
).astype(int)

ks_data["bucket"] = pd.qcut(
    ks_data["score"],
    q=100,
    duplicates="drop"
)

ks_table = (
    ks_data
    .groupby("bucket", observed=True)
    .agg(
        churn=("churn", "sum"),
        non_churn=("non_churn", "sum")
    )
    .sort_index(
        ascending=False
    )
)

ks_table["cum_churn"] = (
    ks_table["churn"]
    .cumsum()
    /
    ks_table["churn"].sum()
)

ks_table["cum_non_churn"] = (
    ks_table["non_churn"]
    .cumsum()
    /
    ks_table["non_churn"].sum()
)

ks_table["ks"] = (
    ks_table["cum_churn"]
    -
    ks_table["cum_non_churn"]
).abs()

ks_statistic = ks_table["ks"].max()

ks_plot = ks_table.reset_index(
    drop=True
)

BG/NBD Benchmark¶

In addition to machine learning models, a probabilistic customer-base model is evaluated as a benchmark.

The BG/NBD model proposed by Fader, Hardie, and Lee estimates the probability that a customer remains active based exclusively on the timing and frequency of historical transactions. Unlike supervised classification approaches, BG/NBD does not require a predefined churn label and instead models customer activity as a latent stochastic process.

BG/NBD Performance¶

The BG/NBD model converged only after increasing the regularization parameter and produced highly concentrated estimates of customer survival probabilities.

Most customers received estimated probabilities of remaining active very close to one, resulting in limited discriminatory power when evaluated against the observed churn labels.

This behavior appears to be related to the transactional structure of the AdventureWorks dataset, where the majority of customers completed only a single purchase during the calibration period. Because BG/NBD relies heavily on repeat-purchase behavior to infer latent customer activity, the scarcity of repeated transactions substantially limits its predictive effectiveness in this setting.

Conclusions¶

This study evaluated customer churn prediction in a non-contractual retail environment using transaction data from the AdventureWorks database.

Several classification algorithms and class-balancing strategies were compared using a temporally separated calibration and validation framework. Among all evaluated alternatives, XGBoost trained on the original dataset achieved the strongest overall performance and substantially outperformed both simpler machine learning models and the BG/NBD probabilistic benchmark.

Key findings include:

  • Recency, Frequency, and Monetary variables all contributed meaningfully to churn prediction.
  • XGBoost provided the best balance between precision and recall while maintaining strong ranking performance.
  • Class-balancing strategies increased recall but did not materially improve overall model performance.
  • The selected model achieved strong customer separation, as demonstrated by the ROC, Precision-Recall, and KS analyses.
  • The BG/NBD benchmark exhibited limited predictive power in this dataset due to the large proportion of customers with only a single observed purchase.
  • The resulting churn probabilities can be used to prioritize customer retention initiatives and support data-driven customer relationship management strategies.

Overall, the results demonstrate that machine learning models built from relatively simple transactional features can provide effective customer churn predictions in non-contractual retail settings.
